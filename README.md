# 校园报修预约系统 — 项目说明书

## 一、项目简介

本系统是一套面向校园场景的**报修预约管理平台**，包含三个端：

| 端 | 技术栈 | 目录 |
|---|---|---|
| 后端服务 | SpringBoot 3 + MyBatis-Plus + MySQL 8 + JWT | `backend/` |
| 前端网页端 | Vue 3 + Vite + Element Plus + ECharts | `frontend/` |
| 微信小程序 | 原生小程序（WXML/WXSS/JS） | `miniprogram/` |

三端共用**同一套后端接口和同一个 MySQL 数据库**，同一账号在小程序和网页登录，身份权限完全一致。

### 角色与权限设计

系统支持四种角色，通过用户表 `role` 字段区分：

| 角色 | 权限说明 |
|---|---|
| 普通用户（USER） | 免费注册。单次报修最多上传 **1 张**故障图片；不能自选预约时间（系统默认派单）；不能标记紧急；仅可查看本人工单；工单完成后可对维修工评价 |
| 会员用户（VIP） | 由管理员开通。单次最多上传 **5 张**图片；可自选预约上门时间；可添加**紧急标记**（工单优先排序）；可查看个人报修统计；工单完成后可对维修工评价；**全部维修服务按基础价 8 折计价（预估费用自动折扣）** |
| 维修管理员（ADMIN） | 全部工单管理（紧急工单置顶优先展示）、接单、指派维修工、修改工单状态、填写维修备注；故障分类动态维护（增删改）；用户管理（开通/取消会员）；维修工管理（新建/编辑/启用停用） |
| 维修工（WORKER） | 由管理员在「维修工管理」中创建或升级。拥有个人档案（姓名、手机号、简介、擅长分类）与统计评分；可查看分配给自己的任务、在抢单大厅抢未指派的待接单工单、完成维修并填写维修备注；仅能处理本人任务 |

报修地点分两大类：**宿舍楼内**（需填楼号+房间号）与**校园公共区域**（需填具体位置）。故障分类按维修工种划分、不区分地点，管理员可在后台动态维护，系统预置水电类、木五金类、土建修缮、空调电器、网络弱电、公共设施、家用电子数码、交通工具维修、家装&管道维修、工业/机房运维、其他小众维修共 11 类；一个工单可选择多个分类，无法归类时选「其他（自行填写）」并填写具体故障类型。

## 二、目录结构

```
campus-repair-system/
├── sql/
│   └── schema.sql          # 建库建表脚本（含初始分类与预置管理员数据）

│   ├── src/main/java/com/campus/repair/
│   │   ├── controller/     # 接口层

│   │   ├── entity/ dto/ vo/# 实体、请求对象、返回对象
│   │   ├── config/         # 拦截器、跨域、静态资源配置
│   │   └── common/         # 统一返回体、业务异常

└── miniprogram/            # 微信小程序
```

## 三、本地运行步骤

### 1. 准备数据库

安装并启动 MySQL 8.0+，执行建表脚本。

**PowerShell（Windows 推荐，支持会提示输入密码）：**

```powershell
mysql --default-character-set=utf8mb4 -u root -p -e "source sql/schema.sql"
```

**CMD：**

```cmd
mysql --default-character-set=utf8mb4 -u root -p < sql/schema.sql
```

> 说明：PowerShell 不支持 `<` 重定向符号，直接输 `mysql -u root -p < sql/schema.sql` 会报「< 运算符是为将来使用而保留的」，请使用上面的 `source` 写法，或先切到 `cmd` 再执行。
>
> 必须带上 `--default-character-set=utf8mb4`，否则 Windows 客户端可能用 GBK/latin1 解析脚本中的中文，出现 `ERROR 1406 Data too long for column 'nickname'` 之类的报错。
>
> 若提示 `Access denied for user 'root'`，说明本机 MySQL 密码不是 `123456`：执行时按提示输入你自己的 root 密码即可，同时把 `backend/src/main/resources/application.yml` 中的 `password` 改成同一个值。

脚本会自动创建数据库 `campus_repair`、全部数据表、11 个预置故障工种分类，并预置一个管理员账号（手机号 `13800000000`）。

### 2. 启动后端（端口 8080）

数据库账号密码通过**环境变量**注入（配置项在 `backend/src/main/resources/application.yml`）：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `MYSQL_HOST` | localhost | 数据库地址 |
| `MYSQL_PORT` | 3306 | 数据库端口 |
| `MYSQL_DB` | campus_repair | 数据库名 |
| `MYSQL_USERNAME` | root | 用户名 |
| `MYSQL_PASSWORD` | 123456 | 密码 |

本机密码不是 `123456` 时，启动前设置环境变量即可，**不用改代码**：

```powershell
# PowerShell（当前窗口有效）
$env:MYSQL_PASSWORD = "你的root密码"
cd backend
mvn spring-boot:run
```

```cmd
:: CMD（当前窗口有效）
set MYSQL_PASSWORD=你的root密码
cd backend
mvn spring-boot:run
```

> IDEA 中运行：`Run → Edit Configurations → Environment variables` 填 `MYSQL_PASSWORD=你的root密码`；永久生效可用 `setx MYSQL_PASSWORD "你的密码"`（新开窗口后生效）。

> **课程演示说明**：本系统采用**模拟短信验证码**，不接入真实短信服务。点击「获取验证码」后，验证码会打印在后端控制台日志中（`模拟发送短信验证码: 手机号=xxx, 验证码=xxx`），直接查看控制台即可登录。

### 3. 启动 Vue 网页后台（端口 5173）

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 http://localhost:5173 ，手机号 + 验证码登录。用预置管理员手机号 `13800000000` 登录即进入管理后台视图。

### 4. 运行微信小程序

用「微信开发者工具」导入 `miniprogram/` 目录（测试号即可），**勾选「详情 → 本地设置 → 不校验合法域名」**后即可在模拟器中运行。

> 真机预览时，把 `miniprogram/app.js` 中的 `baseUrl` 改为电脑的局域网 IP（如 `http://192.168.x.x:8080`），手机与电脑需在同一 WiFi 下。

## 四、核心功能清单

### 微信小程序端
- 首页：广告位轮播（后台配置）、服务保障条、服务分类商城卡片（服务照片 + 基础价 + 会员 8 折价）、快报修入口、报修流程、最近工单与会员权益引导
- 手机号注册、验证码登录
- 普通用户：提交报修（限 1 张图、无预约时间）、查看本人工单（待接单/维修中/已完成/驳回）、查看故障图片
- 会员用户：最多 5 张图、自选预约上门时间、紧急标记、个人报修统计
- 管理员：工单管理（紧急优先、按状态/地点/故障类型筛选、看图）、接单/指派维修工/改状态/填备注、故障分类管理、用户会员管理、维修工管理
- 维修工：我的任务（接单、完成维修并填备注）、抢单大厅（抢未指派的待接单工单）、我的资料（简介、擅长分类、完成数与评分）
- 报修人：工单完成后可在详情页对维修工进行 1~5 星评价
- **课程演示**：首页右上角与「我的」页的角色徽章可点击，同一账号可在普通用户 / 会员 / 维修工 / 管理员之间即时切换，无需退出重登（切到维修工会自动补建维修档案）；该功能仅用于课程演示，真实环境应移除或限制。

### Vue 网页后台
- 同一登录入口，按角色渲染不同菜单
- 顶栏角色胶囊支持一键切换身份（普通用户 / 会员 / 维修工 / 管理员），切换后立即刷新菜单与数据权限。该身份切换为课程演示功能，便于单账号演示四种角色，生产环境应移除该接口与入口
- 工作台首页：欢迎横幅、工单状态统计磁贴、最近工单与快捷入口
- 普通用户：提交报修（遵循免费版限制）、查看本人工单与故障照片、完成后评价维修
- 会员：会员全部权限 + ECharts 报修统计图表
- 管理员：用户管理（开通/取消会员）、工单管理（分页查询、接单、指派维修工、状态流转、维修备注、图片预览、紧急优先）、故障分类增删改、维修工管理（新建/编辑/启停）
- 维修工：我的任务、抢单大厅、个人资料与统计评分

## 五、关键设计说明

1. **权限互通**：小程序与网页共用 `/api/auth/login` 接口，登录签发 JWT（有效期 7 天），后端拦截器统一鉴权，角色判定全部在服务端完成，前端仅做菜单展示控制，保证越权操作被后端拦截。
2. **会员差异控制**：提交工单时后端按角色强制校验——普通用户传多张图、传预约时间、传紧急标记均被拒绝或强制重置，防止绕过前端。
3. **工单状态机**：`待接单 → 维修中 → 已完成`，中间可流转为`驳回`，终态不可逆，非法流转返回业务异常。
4. **紧急工单排序**：管理员工单列表按 `urgent DESC, create_time DESC` 排序，紧急工单始终优先展示。
5. **故障分类动态化且可多选**：分类存于数据库，按维修工种划分、不区分报修地点，管理员可随时新增/编辑/删除；工单与分类通过 `repair_order_category` 关联表支持多选，`repair_order.category_id` 保留为第一个分类（主分类）。已被工单引用的分类执行逻辑删除（停用），保证历史工单数据完整性；无法归类的报修选择「其他（自行填写）」，必须填写具体故障类型。
   > 已有数据库升级请执行：`mysql --default-character-set=utf8mb4 -u root -p -e "source sql/upgrade_multi_category.sql"`（新增关联表、回填历史分类、删除旧预设分类并写入新工种分类；脚本可重复执行）。
6. **图片存储**：采用课程作业简易方案——图片上传到后端本地 `uploads/` 目录，通过静态资源映射访问，数据库只存相对路径。
7. **安全细节**：接口参数用 Bean Validation 校验；SQL 全部走 MyBatis-Plus 参数绑定，无注入风险；统一异常处理返回友好中文提示。
8. **界面设计**：网页端与小程序统一采用一套设计语言——品牌渐变（`#2c6bf2 → #17bfd4`）、深色侧边栏、大圆角卡片、胶囊状态标签与柔和投影；状态色固定为待接单琥珀 `#f5a524`、维修中品牌蓝 `#2c6bf2`、已完成薄荷绿 `#0fb583`、驳回红 `#ef4b4b`。网页端全局样式集中在 `frontend/src/styles/theme.css`，小程序全局样式集中在 `miniprogram/app.wxss`。
9. **维修工与派单/抢单**：维修工档案存于 `repair_worker`，擅长分类通过 `repair_worker_category` 关联；工单 `worker_id` 记录负责维修工。管理员可指定维修工（派单），维修工也可在抢单大厅领取未指派的待接单工单（抢单），两者都写入 `worker_id`；维修工只能操作本人任务，完成后由报修人评分（`rating_score/rating_comment/rating_time`），档案统计实时汇总完成数与平均评分。
   > 已有数据库升级请执行：`mysql --default-character-set=utf8mb4 -u root -p -e "source sql/upgrade_worker.sql"`（新增维修工档案表、擅长分类表与工单维修工/评分类字段；脚本可重复执行）。
10. **服务价格与广告位**：`fault_category` 增加 `price`（基础服务价）与 `image_url`（服务照片），首页与提交页明码标价；提交报修时后端按所选分类价格求和并写入 `repair_order.estimated_price`，VIP 自动按 **8 折**计算（保留两位），选择「其他」则为面议。首页广告位数据来自 `ad_banner`（标题、副标题、图片、排序、启用状态），接口 `GET /ads` 按 `sort` 升序返回启用广告，图片使用远程生成地址。
   > 已有数据库升级请执行：`mysql --default-character-set=utf8mb4 -u root -p -e "source sql/upgrade_service_mall.sql"`（新增价格/图片/预估费用字段与广告位表，并同步 11 个分类价格与服务图片；脚本可重复执行）。
